# Gates ERP — نسخة الـ exe (On-Premise) والتراخيص

النسخة دي بتشتغل على **سيرفر واحد عند العميل** (ويندوز)، وباقي الموظفين يفتحوا البرنامج من
المتصفح على الشبكة الداخلية. الداتابيس MySQL بتاعة العميل نفسه.

---

## 1. الترخيص — بيشتغل إزاي

```
 العميل                                   إنت (Gates)
 ──────                                   ───────────
 GatesERP.exe ──► كود الجهاز ──────────►  license-tool.ts issue
                 (XXXXX-XXXXX-XXXXX-XXXXX)   + اسم العميل + عدد اليوزرز + تاريخ الانتهاء
                                              │  يوقّع بالمفتاح السري بتاعك
 gates.lic  ◄────────────────────────────────┘
 (يتحط جنب GatesERP.exe)
```

| الحماية | إزاي |
|---|---|
| **محدش يقدر يزوّر ترخيص** | الملف موقّع بـ Ed25519. المفتاح السري عندك بس (`~/.gates-license/gates-license-private.pem`). البرنامج فيه المفتاح العام بس، يقدر *يتحقق* لكن مايقدرش *يعمل* ترخيص. |
| **أي تعديل في الملف يبوظه** | تغيير عدد اليوزرز أو التاريخ أو الجهاز ← التوقيع يفشل ← البرنامج يرفض. |
| **مربوط بالجهاز** | كود الجهاز = بصمة من `MachineGuid` بتاع ويندوز + `UUID` اللوحة الأم. نسخ المجلد لجهاز تاني ← كود مختلف ← الترخيص يترفض. |
| **حد اليوزرز** | عند إضافة يوزر أو تفعيله: لو اليوزرز النشطين (في كل الشركات) وصلوا للحد ← رفض. ولو حد ضاف يوزرز من الداتابيس مباشرة: أقدم N يوزر بس يقدروا يدخلوا (المدير الأصلي دايماً يدخل). |
| **مدة الترخيص** | دايم أو لحد تاريخ. بيتشيك عند التشغيل وكل ساعة؛ لو انتهى السيرفر يقف. ولو العميل رجّع تاريخ الجهاز لقبل تاريخ إصدار الترخيص ← رفض. |
| **التحقق جوه السيرفر نفسه** | مش في الـ launcher بس. حتى لو حد شغّل `node index.js` مباشرة، السيرفر يرفض يقوم بدون ترخيص صحيح. وضع الترخيص متجمّع جوه الكود (compile-time) — مفيش متغير بيئة يقفله. |
| **الكونكشن سترنج** | بيتخزن في `data\config.dat` مشفّر AES-256-GCM بمفتاح مشتق من كود الجهاز؛ لو اتنسخ لجهاز تاني مايتقريش. |
| **Railway مش متأثر** | كل ده شغال بس في بناء الـ exe. الموقع الحالي `isOnPremMode() = false` ومفيش أي تغيير في سلوكه. |

### حدود لازم تعرفها
- أي برنامج بيشتغل على جهاز العميل ممكن في الآخر حد محترف يفكّه ويعدّل في الكود نفسه
  (مثلاً يشيل التحقق). اللي عملناه بيمنع **التزوير والنسخ والتلاعب العادي**، وبيخلي
  الكسر محتاج هندسة عكسية فعلية للكود المضغوط. ده المستوى الطبيعي لأي برنامج offline.
- **المفتاح السري هو كل حاجة.** لو اتسرّب، أي حد يقدر يطلع تراخيص. خد منه نسخة احتياطية
  في مكان آمن (فلاشة مشفّرة / password manager). ماتحطوش في الـ repo (الـ repo عام).
  لو ضاع: لازم مفتاح جديد + نسخة exe جديدة + إعادة إصدار كل التراخيص.
- لو العميل غيّر اللوحة الأم أو سطّب ويندوز من جديد، كود الجهاز هيتغير ← اعمل له ترخيص جديد.

## 2. أداة الترخيص (على جهازك إنت بس)

من مجلد `gates-backend`:

```bash
# إصدار ترخيص
npx tsx scripts/onprem/license-tool.ts issue --machine ABCDE-12345-ABCDE-12345 --customer "شركة النور" --users 10 --expires 2027-12-31 --out ~/Desktop/gates.lic

# ترخيص دايم
npx tsx scripts/onprem/license-tool.ts issue --machine ABCDE-12345-ABCDE-12345 --customer "شركة النور" --users 10 --expires never --out ~/Desktop/gates.lic

# قراءة أي ملف ترخيص
npx tsx scripts/onprem/license-tool.ts inspect ~/Desktop/gates.lic

# كل التراخيص اللي طلّعتها (سجل في ~/.gates-license/issued.jsonl)
npx tsx scripts/onprem/license-tool.ts list
```

- **زيادة يوزرز / تجديد:** اعمل ترخيص جديد لنفس كود الجهاز وابعته؛ العميل يستبدل `gates.lic`
  ويعيد تشغيل البرنامج.
- **إيقاف عميل:** في وضع offline مفيش إيقاف عن بعد. استخدم تراخيص بتاريخ انتهاء (سنوي مثلاً)
  ومتجددش للي مش دافع.

## 3. بناء الـ exe

```bash
# 1) بناء الويب (الـ proxy لازم يشاور على السيرفر المحلي)
cd gates-web && NEXT_PUBLIC_API_URL= BACKEND_PROXY_TARGET=http://127.0.0.1:3001 npx next build

# 2) تجميع حزمة ويندوز
cd .. && node gates-onprem/build-windows.mjs
```

الناتج: `gates-onprem/out/GatesERP-<version>-win-x64/` و `.zip`. السكريبت بيعمل:
bundle للباك إند (مضغوط، بدون source maps، والترخيص متجمّع جواه) ← مكتبات ويندوز + محرك Prisma
لويندوز ← `baseline.sql` (الجداول كلها للداتابيس الفاضية) ← الويب ← `node.exe` الرسمي (متحقق
بالـ SHA256) ← `GatesERP.exe` ← فحص أمان (مفيش `.env` ولا مفاتيح ولا source maps) ← zip.

> ⚠️ أول نسخة اتبنت من شجرة التطوير الحالية (فيها شغل لسه مش committed). قبل ما تبيع لعميل
> حقيقي، ابنِ من commit معروف بنفس فكرة الـ release worktree.

## 4. عند العميل

1. ينسخ المجلد لـ `C:\GatesERP` ويشغّل `GatesERP.exe`.
2. يظهر كود الجهاز ← يبعته لك ← تبعتله `gates.lic` ← يحطه جنب البرنامج.
3. يحط الكونكشن سترنج (`mysql://user:pass@host:3306/db`) على داتابيس **فاضية**.
4. البرنامج يعمل الجداول، ويسأل عن اسم الشركة وحساب المدير الأول.
5. يفتح على `http://localhost:3000`، والأجهزة التانية على `http://<اسم-السيرفر>:3000`.

`GatesERP.exe --machine-code` يطبع الكود · `GatesERP.exe --change-db` يغيّر الداتابيس ·
اللوجات في `data\logs\`.

## 6. حاجات لسه مش موجودة في النسخة الأولى
- **Redis مقفول:** المهام اللي في الخلفية (التصدير/الاستيراد الكبير، المهام المجدولة) مش هتشتغل.
- **مش Windows Service:** البرنامج شغال طول ما النافذة مفتوحة. الخطوة الجاية: تسطيبه كخدمة + installer.
- **غير موقّع (Authenticode):** ويندوز SmartScreen هيحذّر. محتاج شهادة توقيع كود قبل البيع.
- **التحديثات:** نسخة جديدة فيها migrations جديدة محتاجة آلية تحديث (لسه مش مبنية).
